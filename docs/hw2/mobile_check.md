# Проверка формы заявки с эмулятора Android (пробег 400001)

Дата прогона: 2026-10-22.
Цель: открыть форму заявки в браузере эмулятора Android, отправить её с пробегом `400001` и зафиксировать решение системы.

## Как это делалось

Мобильный MCP-сервер `mcp-devices` (версия 4.4.1) уже был прописан в `kilo.jsonc:16`
(`"mobile": { "type": "local", "command": ["mcp-devices"], "enabled": true }`), платформа `android`
включена, `mcp-devices doctor android` → `android: ok (adb)`.

Оговорка: инструменты этого MCP **не были подставлены в мой список инструментов автоматически**,
поэтому я не мог нажимать `ui`/`input`/`screen` как готовые вызовы. Вместо этого я запустил тот же
сервер `mcp-devices` из конфига вручную и говорил с ним по его штатному JSON-RPC протоколу
(stdin/stdout) небольшим драйвером `/tmp/kilo/mcpdrive.py` (вне репозитория). Сервер, профиль и
устройство — те же самые; отличается только транспорт вызовов.

Ось в эмуляторе по текущему MCP-состоянию:

```
mcp-devices platforms   → Enabled: android
mcp-devices doctor android → android: ok (adb)
device list             → emulator-5554 - sdk_gphone64_x86_64 (emulator, device)
```

## Пошагово

1. **Проверил, что сервис живой с хоста.**
   `curl http://localhost:8080/health` → `200`.

2. **Открыл адрес в Chrome на эмуляторе.**
   `adb -s emulator-5554 shell am start -a android.intent.action.VIEW -d "http://10.0.2.2:8080/" -n com.android.chrome/...`
   `10.0.2.2` — стандартный адрес хоста, видимый из Android-эмулятора.
   Отдельно проверил связность: `adb shell ping -c 1 10.0.2.2` → `1 packets transmitted, 1 received`.
   (С самого хоста `curl http://10.0.2.2:8080/health` не отвечает — это ожидаемо, этот адрес имеет
   смысл только внутри эмулятора.)

3. **Прошёл первый запуск Chrome.** На экране было `FirstRunActivity`:
   - тапнул «Use without an account» (`com.android.chrome:id/signin_fre_dismiss_button`, 540×2093);
   - на диалоге «Chrome notifications make things easier» тапнул «No thanks»
     (`com.android.chrome:id/negative_button`, 592×1753).

4. **Убедился, что форма загрузилась.** `ui tree` показал WebView с заголовком
   «Предварительная оценка заявки — carmoney-lab» и семь полями формы с дефолтами.

5. **Поставил пробег 400001.**
   - `ui tree` → поле пробега `EditText "84000, Пробег, км"`, индекс `23`, координаты (540, 1538);
   - `input tap index=23` — фокус в поле, поднялась клавиатура;
   - `input key key=MOVE_END` — **не сработало**: `[TOOL_FAILED] Unknown key: MOVE_END`.
     Обходной путь: шесть раз `input key key=DELETE` (в поле было 5 символов «84000», курсор стоял
     в конце после тапа) — поле очищено;
   - `input text text=400001` → «Entered 6 character(s).»;
   - контрольная проверка `ui tree`: поле читается как `EditText "400001, Пробег, км"`.

6. **Скрыл клавиатуру** (`input key key=BACK`), чтобы не перекрывать кнопку отправки.

7. **Отправил заявку.** `input tap index=30` — кнопка «Отправить заявку» (292, 2288).

8. **Прокрутил страницу вниз** (`input swipe` 540×1900 → 540×900), чтобы блок «Решение» целиком
   попал в кадр: после прокрутки элементы результата оказались на y = 1724…2170 при высоте экрана 2400.

9. **Снял скриншот через MCP**: `screen action=capture, compress=false, waitForStable=true`.
   Ответ пришёл как image-блок `image/png` (base64), драйвер декодировал его в
   `docs/hw2/mobile_check.png` — файл 1080×2400, 138 836 байт.
   Fallback `adb exec-out screencap -p` не понадобился: MCP умеет отдавать файл сам.

## Что показала система

Значения, снятые из accessibility-дерева результата на экране после отправки:

| Поле | Значение на экране |
|---|---|
| Решение | `REVIEW` |
| LTV | `50 %` |
| Возраст авто | `7 лет` |
| Одобренный лимит | `0 ₽` |
| Номер заявки | `31` |

Проверка со стороны сервера — `docker compose logs backend`:

```
[Thu Oct 22 10:33:41 2026] 172.26.0.1:43388 Accepted
[Thu Oct 22 10:33:41 2026] application=31 ltv=50 decision=review limit=0
```

Значения на экране и в логе сервиса совпадают.

## Почему именно `review`

- Поля кроме пробега остались дефолтными: клиент `CL-0025`, VIN `XTA21099998765432`,
  год `2019`, стоимость `900000`, сумма `450000`, срок `24` мес.
- LTV = 450000 / 900000 = 50 %, а `approve_max` = 60.0 (`backend/config/rules.php:45`) — по LTV
  заявка проходит в `approve`.
- Но `max_mileage_for_approve_km` = 400000 (`backend/config/rules.php:24`), а пробег 400001
  на 1 км больше. Правило пробега в `backend/src/Domain/DecisionEngine.php:43` понижает
  `approve` до `review`.
- Отдельной проверки «пробег не больше 500000» (`max_mileage_km`, `backend/config/rules.php:23`)
  заявка не задела: 400001 < 500000, поэтому валидатор
  (`backend/src/Domain/ApplicationValidator.php:44`) ошибку не вернул.

## Чего я не смог проверить и о чём предупреждаю

- **Скриншот я не видел глазами.** В этой модели отключён ввод изображений, поэтому PNG я проверил
  только технически (сигнатура и корректность PNG, размеры 1080×2400). Содержимое кадра
  подтверждено accessibility-деревом и логом бэкенда, а не просмотром картинки.
- Прокрутка результата сделана свайпом по WebView, координаты кнопок брались из `ui tree`; если
  локальная вёрстка или размер окна Chrome отличаются, координаты могут съехать — в этом прогоне
  не съехали, все тапы попали по целям (MCP подтверждал это подсказками по изменившимся элементам).
- Заявка №31 — запись в учебной базе, её создание является побочным эффектом проверки.

## Сверка человеком

- Скриншот `docs/hw2/mobile_check.png` просмотрен: в поле «Пробег, км» — `400001`, в блоке «Решение» — `REVIEW`, LTV `50 %`, возраст `7 лет`, лимит `0 ₽`, заявка `31`. Совпадает с таблицей выше и с логом сервиса (`application=31 ltv=50 decision=review limit=0`).
- Шаги сверены с лентой сессии Kilo: очистка поля — `MOVE_END` упал, затем шесть `DELETE`, затем ввод `400001`; все вызовы `input` / `ui` / `screen` шли в `mcp-devices` через самописный драйвер.
- Ссылка на правило пробега исправлена: в `backend/src/Domain/DecisionEngine.php:14` — комментарий, сама проверка — `backend/src/Domain/DecisionEngine.php:43`.
- **Почему инструменты MCP не попали в сессию.** В `kilo.jsonc` блок `"mobile"` вписан не внутрь `"mcp"`, а отдельным ключом верхнего уровня, рядом с `"permission"` и `"mcp"` — Kilo его как MCP-сервер не читает. Агент этого не заметил и написал, что сервер «уже был прописан в `kilo.jsonc:16`».

## ★ Сравнение с браузерной проверкой 2.1.3

Тот же кейс — пробег 400001, ожидание `review` — в 2.1.3 проверялся через Playwright MCP (`docs/setup/e2e_check.md`). Решение одно и то же (`review`, LTV 50 %), сложность — разная.

| | Браузер, Playwright (2.1.3) | Эмулятор, mcp-devices (ДЗ 2.6) |
|---|---|---|
| Подготовка | `npx @playwright/mcp`, одна строка в `kilo.jsonc` (плюс `--headless` из-за падения Chrome) | Android SDK без Studio (~3 ГБ), создание AVD, KVM, запуск эмулятора, `adb` в PATH, глобальный `mcp-devices` + плагин Android |
| Адрес сервиса | `http://localhost:8080` | `http://10.0.2.2:8080` — `localhost` внутри эмулятора — сам эмулятор |
| До формы | сразу | экраны первого запуска Chrome («Use without an account», «No thanks») — два лишних тапа |
| Как агент «видит» страницу | снимок DOM: роли и подписи полей (`spinbutton "Пробег, км"`) | дерево доступности Android: `EditText "84000, Пробег, км"` с индексом и координатами; без MCP `uiautomator dump` содержимое WebView вообще не показал |
| Ввод значения | `fill_form` — поле заменяется целиком | тап → клавиатура → очистка по символу (`MOVE_END` не поддержан, шесть `DELETE`) → ввод → `BACK`, чтобы клавиатура не закрывала кнопку |
| Результат на экране | весь блок в снимке, скриншот full page | блок «Решение» ниже экрана — нужен свайп, скриншот только видимой области |
| Скриншот | `take_screenshot` сразу в файл | `screen capture` отдаёт base64; лимит `maxHeight ≤ 2000` (первый вызов упал), в файл сохранял драйвер |
| Подключение MCP | инструменты появились в сессии | не появились (ошибка в `kilo.jsonc`, см. выше) — агент сам написал JSON-RPC-клиент |
| Цена | 5 вызовов Playwright на кейс | 42 шага, 44 вызова инструментов, ~16 мин, 117k входа + 1,66 млн из кэша |

Почему сложнее:

1. **Больше слоёв между агентом и формой.** В браузере MCP говорит с DOM напрямую. На эмуляторе цепочка такая: MCP → `adb` → Android → Chrome → WebView, и каждый слой добавляет своё: сеть эмулятора (`10.0.2.2`), first-run Chrome, экранную клавиатуру.
2. **Взаимодействие как у пальца, а не у скрипта.** Нет «заполнить поле значением» — есть тап, нажатия клавиш и свайпы по координатам. Поэтому очистка поля стала отдельной задачей, а результат пришлось прокручивать в кадр.
3. **Проверка результата слабее.** MiniMax M3 не читает картинки, так что скриншот агент глазами не видел. Решение он подтвердил деревом доступности и логом сервиса, а сверку картинки сделал человек. В 2.1.3 текст результата приходил прямо в снимке страницы.
4. **Больше точек отказа в окружении.** Падение Chrome было и в 2.1.3, но здесь сломалось само подключение MCP. Агент честно это написал, но причину — ошибку в `kilo.jsonc` — не нашёл.
