# 1.2.1 — ask и code: один промпт, два агента

Промпт: «В README не хватает раздела „Как проверить, что сервис жив“… добавь такой раздел в README».

- **ask** — запросил чтение Makefile и docker-compose.yml, думал около 5 минут. README не изменил: в ответе выдал готовые блоки текста с описанием, что и куда вставить. Править файл остаётся человеку.
- **code** — прочитал те же файлы, предложил изменить README и после моего подтверждения (Run) сам внёс правку: `git status` показал `modified: README.md` (+30 строк).
- Разница: ask только читает и советует, code ещё и пишет в файлы — с запросом разрешения на действие.
- Для разбора кода возьму **ask**: он ничего не поменяет случайно, а правки потом можно отдать code осознанно.

## ★ Что можно каждому агенту

Группы прав из встроенных режимов Kilo Code (плагин 5.16.1): read — читать файлы, edit — править, command — запускать команды в терминале, browser — браузер, mcp — MCP-серверы.

- **code** — всё: read, edit, command, browser, mcp. Пишет и меняет код.
- **ask** — только read, browser, mcp. Ничего не правит и не запускает, только отвечает.
- **plan** (в плагине называется Architect) — read, browser, mcp; edit только для `.md` файлов (план), код не трогает и команды не запускает.
- **debug** — всё, как code: read, edit, command, browser, mcp. Плюс инструкция сначала искать причину и добавлять логи, а фикс делать после подтверждения.
