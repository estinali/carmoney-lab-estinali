# Код-ревью перед мержем

## Порядок работы
1. Ревью только по диффу PR; не предлагать переделать то, что вне задачи PR. Проблема рядом с диффом — отдельной строкой «вне PR», вердикт она не меняет.
2. Код при ревью не правлю: ревьюер только пишет замечания, исправляет автор.
3. Пороги в rules.php и ожидания в тестах сам не меняю, даже если кажутся неверными, — отмечаю и спрашиваю человека.
4. Имена, стиль и форматирование — максимум minor, не blocker.
5. Результат — в чат. Файл в docs/ не создаю, если человек не попросил. Это не отчёты из docs/review/README.md (selfreview, судья, вердикты по спеке) — там свой формат.

## Формат результата
- Ответ собирать по шаблону [template.md](template.md).
- Список замечаний к PR и итоговый вердикт.
- Каждое замечание одной строкой: severity (blocker / major / minor) · файл:строка · что не так · почему это проблема (ссылка на требование, спеку или правило из AGENTS.md, если есть).
- Без общих слов вроде «стоит улучшить читаемость» — каждое замечание с файл:строка и конкретикой.
- В конце вердикт одним словом: можно мержить / мержить после правок (есть major) / нельзя мержить (есть хоть один blocker).
- Под вердиктом — что проверено, а что нет: непроверенное пишем «не проверено», а не «ок».

## Чек-лист — обязательно проверить
1. Соответствие задаче: изменения делают то, что в спеке или intent (docs/spec/, docs/intent/), и ничего лишнего.
2. Тесты: под новое поведение есть тест, под баг — тест, который сначала был красным; make test и make lint зелёные.
3. Пороги и лимиты берутся из backend/config/rules.php, а не захардкожены; сами значения в rules.php и ожидания в тестах не поменяли без решения человека.
4. Конвенции: declare(strict_types=1), классы final, namespace CarMoneyLab\, тесты по AAA и заканчиваются assert'ом.
5. Безопасность и данные: в диффе нет секретов, .env, реальных VIN или ПДн; SQL только через подготовленные запросы.
6. Граничные случаи: значения ровно на пороге (< или <=), пустые и отсутствующие поля.

## Severity
- **blocker** — нельзя мержить: тесты красные или make lint падает; новое поведение без теста или баг-фикс без теста, воспроизводящего баг; порог захардкожен вместо rules.php или значения в rules.php / ожидания в тестах поменяли без решения человека; секреты, .env, реальные VIN или ПДн в диффе; SQL с подстановкой данных пользователя в строку запроса; поведение расходится со спекой (сделано не то или сломано существующее).
- **major** — мержить после правок: граничный случай не покрыт (< вместо <=), нарушены конвенции (strict_types, final), тест без assert'а.
- **minor** — на усмотрение автора: имена, комментарии, форматирование.
